The two most common problems with pulling Docker images, and their fixes.

## The server cannot pull images

On some servers, especially in Russia, Docker Hub is unreachable and images do not download (see issue [#40](https://github.com/eGamesAPI/remnawave-reverse-proxy/issues/40)). The fix is registry mirrors.

<Steps>

1. Create or open the `daemon.json` file:

    ```bash
    nano /etc/docker/daemon.json
    ```

2. Paste the mirror configuration:

    ```json title="daemon.json"
    {
    "log-driver": "local",
    "registry-mirrors": [
        "https://mirror.gcr.io/",
        "https://dockerhub.timeweb.cloud"
        ]
    }
    ```

3. Restart the Docker service:

    ```bash
    systemctl restart docker
    ```

4. Check that the mirrors were picked up:

    ```bash
    docker info | grep -A 3 "Registry Mirrors"
    ```

</Steps>

## You have reached your unauthenticated pull rate limit

This message means the download limit for anonymous requests to Docker Hub is exhausted. What you can do:

<Steps>

1. Log in to Docker Hub:

    ```bash
    docker login
    ```

    Authenticated requests are counted per account, not per server address.

2. Change the server's external address

    The limit is tied to the IP: if the address is dynamic, restarting the server helps; otherwise ask your hoster about changing the address.

3. Enable IPv6

    Run `remnawave_reverse`, select item `9` (`Manage IPv6`), and enable IPv6 support. Downloads then go from a different address, and the limit often lets go.

</Steps>
