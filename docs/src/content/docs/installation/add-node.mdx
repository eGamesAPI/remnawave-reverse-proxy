## Running the script

:::danger[Important]
The script must be run as **root**, and on the server where the RemnaWave panel is installed.
:::

Run this command on your server:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/install_remnawave.sh)
```

:::danger[If GitHub is unreachable]
Run the installer from the jsDelivr mirror:

```bash
bash <(curl -Ls https://cdn.jsdelivr.net/gh/eGamesAPI/remnawave-reverse-proxy@main/install_remnawave.sh)
```
:::

## Automatic installation

The panel sets the node up on its server itself: it connects over SSH, prepares the server and brings the containers up. You never have to log into the node server.

**What you need:**

- a separate server with Debian or Ubuntu and root SSH access. A password is enough: the script installs its own key, never stores the password and never asks again.
- the node's domain, for example `node.example.com`.
- port 443 free on the node server. For Caddy port 80 must be free too; the script adds the firewall rule itself.

:::tip[Domain and DNS]
If the domain's A record already points at the node server, installation takes the shortest path. If there is no record, the script creates it through your DNS provider's API: Cloudflare, Gcore or Bunny.net, asking for a missing key once and remembering it. Without an API it shows which record to add by hand.
:::

**How the installation goes:**

<Steps>

1. **SSH connection.** If access to this server is already configured in the [SSH access](/configuration/ssh-remote-access/) section, it is used silently. For a domain without an A record the script asks for the server IP, and that is the only extra question.

2. **DNS record.** If the record does not exist, the script creates it. A zone whose certificate already lives on the panel is recognized automatically. For a new zone the script asks which DNS provider to use.

3. **Server preparation.** The script installs packages and Docker with mirrors for when downloads are blocked, brings up ufw with port 443 open and SSH preserved.

4. **Link key and certificate.** First the script issues the node's link key. Then the certificate: if the panel's wildcard already covers the node domain (`*.example.com` covers `node.example.com`), the files are copied to the node and the panel carries renewals over itself. If not, the certificate is issued right on the node server via a DNS check and renewed there, without the panel. With Caddy it is simpler still: Caddy issues and renews the certificate itself, the panel is not involved.

5. **Launch.** The script generates the camouflage site, writes the configuration and brings up the node and web server containers.

6. **Connectivity check.** The script waits for the node to report to the panel. If the DNS record is very fresh and the panel's resolvers do not see it yet, the script hands the address to the panel directly and the connection goes through.

</Steps>

When you see `The node server is set up, the node is running`, the installation is finished. Check that the node glows green in the panel's Nodes section and that its domain opens the camouflage site in a browser.

:::note[Replacing an existing node]
If a node container already runs on the server, the script always asks before replacing it. An accidental reinstall is impossible.
:::

:::note[If something went wrong]
The node is already created in the panel by that point. The script offers to retry, and if you decline, it shows how to finish the installation manually.
:::

## Manual installation

The script creates the node, profile and host in the panel; you install the server yourself.

<Steps>

1. Enter your new domain for `selfsteal`, which the node will use to connect to the panel, and a name for the node itself.

    :::danger[Important]
    Do not forget to add the DNS record for your domain.
    :::

    <Terminal title="root@server: ~" lines={[
      { kind: 'plain', text: "Enter the node's selfsteal domain (the address from its card in the panel): ", answer: 'node.example.com' },
      { kind: 'plain', text: 'Enter a name for your node (e.g. Germany): ', answer: 'Germany' },
    ]} />

2. Once the node is added to the panel, run the script on the new server that will host the RemnaWave node, select `Install Remnawave Components`, then [`Install only the node`](https://wiki.egam.es/installation/node-only/).

</Steps>
