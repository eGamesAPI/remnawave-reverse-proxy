## Running the script

:::danger[Important]
The script must be run as **root**.
:::

Run this command on your server:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/install_remnawave.sh)
```

:::danger[If GitHub is unreachable]
Run the installer from the jsDelivr mirror:

```bash
bash <(curl -Ls https://cdn.jsdelivr.net/gh/eGamesAPI/remnawave-reverse-proxy@main/install_remnawave.sh)
```
:::

## Installing only the subscription page

Use this option when the panel already lives on another server and you want the subscription page on its own server, for example so user traffic does not pass through the panel server.

:::note
Prepare an **API token** in the panel beforehand: `Settings` → `API tokens`
:::

### What the installer does

1. **Checks the server before starting**: the subscription page is not installed yet, port 443 is free.
2. **Asks for three things**: the subscription domain (validated together with its DNS record), the already installed panel's domain and the panel's API token.
3. **Finds out how the panel is protected**: cookie, TinyAuth login page or the Caddy portal, and asks for the matching key: the cookie, a login and password, or an API key.
4. **Issues a certificate** for the subscription domain (DNS API, ACME or your own) and sets up renewal.
5. **Writes the services into `/opt/subscription`**: the subscription page container and the web server in front of it; files are created root-only.
6. **Starts and verifies**: requests `https://domain` up to 5 times with a 15-second pause until the page answers.
7. **Shows the final screen**: the page address, a reminder to set `SUB_PUBLIC_DOMAIN` in the panel and a warning about the cookie match.

## Updating the script

1. Open the script menu with the `remnawave_reverse` command (or the short alias `rr`) and select item `12`, `Check for updates script`. When an update is already found, the item lights up red and reads `Update script`:
