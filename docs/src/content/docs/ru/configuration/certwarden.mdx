**Cert Warden** хранит SSL-сертификаты в одном месте и раздаёт их серверам: сам получает и продлевает их по ACME (Let's Encrypt), а клиенты забирают файлы по API-ключам и перезапускают свои сервисы. Это удобно, когда доменов и серверов много: вместо certbot на каждой машине один сервер отвечает за все сертификаты.

## Как это работает

<CertwardenDiagram lang="ru" />

Cert Warden заказывает сертификаты у Let's Encrypt и доказывает владение доменом DNS-01-записью у DNS-провайдера. Готовые сертификаты он хранит у себя и раздаёт клиентам по API-ключам: клиент на каждом сервере скачивает pem-файлы, кладёт их на диск и перезапускает свой веб-сервер. Панели за Caddy файловые сертификаты не нужны: Caddy получает их сам.

## Установка Cert Warden

:::danger[Важно]
Устанавливать **Cert Warden** будем на сервер панели **Remnawave**, но вы можете установить его на любой другой сервер. Владение доменом проверяем методом DNS-01: ниже разобраны Cloudflare, Gcore и Bunny.net.
:::

<Steps>

1. Создаём директорию для Cert Warden и файл `docker-compose.yml`:

    ```bash
    mkdir /opt/certwarden && cd /opt/certwarden && nano docker-compose.yml
    ```

    Вставляем следующее содержимое:

    ```yaml title="docker-compose.yml"
    services:
      certwarden:
        container_name: certwarden
        image: ghcr.io/gregtwallace/certwarden:latest
        restart: unless-stopped
        ports:
          - '127.0.0.1:4050:4050'
        volumes:
          - ./certwarden-data:/app/data
        networks:
          - remnawave-network
        logging:
          driver: 'json-file'
          options:
            max-size: '30m'
            max-file: '5'

    networks:
      remnawave-network:
        name: remnawave-network
        driver: bridge
        external: true
    ```

2. Запускаем Cert Warden:

    ```bash
    cd /opt/certwarden && docker compose up -d && docker compose logs -f
    ```

3. Добавляем Cert Warden в веб-сервер панели, чтобы его интерфейс был доступен по своему домену:

    <Tabs>
    <TabItem label="Nginx">

    ```bash
    cd /opt/remnawave && nano nginx.conf
    ```

    Добавляем секцию upstream:

    ```nginx title="nginx.conf"
    upstream certwarden {
        server 127.0.0.1:4050;
    }
    ```

    Добавляем секцию server:

    ```nginx title="nginx.conf" "yourdomain.com"
    server {
        listen 443 ssl;
        server_name certwarden.yourdomain.com; # Не забудьте добавить запись DNS в Cloudflare
        http2 on;

        ssl_certificate "/etc/nginx/ssl/yourdomain.com/fullchain.pem";
        ssl_certificate_key "/etc/nginx/ssl/yourdomain.com/privkey.pem";
        ssl_trusted_certificate "/etc/nginx/ssl/yourdomain.com/fullchain.pem";

        location / {
            proxy_pass http://certwarden;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
    ```

    Перезапускаем nginx:

    ```bash
    cd /opt/remnawave && docker compose down remnawave-nginx && docker compose up -d remnawave-nginx
    ```

    </TabItem>
    <TabItem label="Caddy">

    ```bash
    cd /opt/remnawave && nano Caddyfile
    ```

    Добавляем в конец файла сайт Cert Warden:

    ```caddyfile title="Caddyfile" "yourdomain.com"
    certwarden.yourdomain.com {
        reverse_proxy 127.0.0.1:4050
    }
    ```

    Сертификат на этот домен Caddy получит сам, как и для панели.

    Перезапускаем Caddy:

    ```bash
    cd /opt/remnawave && docker compose restart remnawave-caddy
    ```

    </TabItem>
    </Tabs>

4. Открываем браузер и переходим по ссылке:

    :::danger[Важно]
    Не забываем добавить запись DNS для вашего домена у провайдера DNS.
    :::

    ```bash "yourdomain.com"
    https://certwarden.yourdomain.com
    ```

5. Входим в систему, используя логин `admin` и пароль `password`:

    <div style={{ display: 'flex', justifyContent: 'center' }}>
      <img
        src="https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_login.png"
        alt="Cert Warden Login"
        style={{ maxWidth: '50%' }}
      />
    </div>

6. Попадаем на главную страницу:

    ![Cert Warden dashboard](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_dashboard.png)

7. Переходим в раздел `Settings` и меняем текущий пароль.

</Steps>

## Настройка Provider

Провайдер отвечает за DNS-записи при проверке домена. У Cloudflare в Cert Warden есть нативный провайдер, Gcore и Bunny.net подключаются через встроенный движок lego.

<Tabs>
<TabItem label="Cloudflare">

<Steps>

1. Переходим в раздел `Providers` и нажимаем `New Provider`.

2. Выбираем `DNS-01 Cloudflare`.

3. В поле `Domains` вводим домен, для которого будем получать wildcard-сертификаты.

4. В поле `API Access Method` выбираем `API Token`. Инструкцию по созданию токена с правами `Zone:Edit` можно найти в [официальной документации Cloudflare](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/).

    <div style={{ display: 'flex', justifyContent: 'center' }}>
      <img
        src="https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_new_challenge_provider.png"
        alt="Cert Warden New Challenge Provider"
        style={{ maxWidth: '60%' }}
      />
    </div>

5. Нажимаем `Submit`.

</Steps>

</TabItem>
<TabItem label="Gcore">

<Steps>

1. Переходим в раздел `Providers` и нажимаем `New Provider`.

2. Выбираем `DNS-01 go-acme (le-go)`.

3. В поле `Domains` вводим домен, для которого будем получать wildcard-сертификаты (например, `*.example.com`).

4. В поле `Code` вводим код провайдера: `gcore`.

5. В поле `Environment Variables` добавляем постоянный API-токен из панели Gcore в формате `ИМЯ=ЗНАЧЕНИЕ`, без слова `export`:

    ```text "GCORE_PERMANENT_API_TOKEN"
    GCORE_PERMANENT_API_TOKEN=ваш_постоянный_токен
    ```

6. Нажимаем `Submit`.

</Steps>

</TabItem>
<TabItem label="Bunny.net">

<Steps>

1. Переходим в раздел `Providers` и нажимаем `New Provider`.

2. Выбираем `DNS-01 go-acme (le-go)`.

3. В поле `Domains` вводим домен, для которого будем получать wildcard-сертификаты (например, `*.example.com`).

4. В поле `Code` вводим код провайдера: `bunny`.

5. В поле `Environment Variables` добавляем Access Key из аккаунта bunny.net в формате `ИМЯ=ЗНАЧЕНИЕ`, без слова `export`:

    ```text "BUNNY_API_KEY"
    BUNNY_API_KEY=ваш_ключ
    ```

6. Нажимаем `Submit`.

</Steps>

</TabItem>
</Tabs>

:::note
Полный список кодов провайдеров и их переменных приведён в [документации lego](https://go-acme.github.io/lego/dns/). Cert Warden перенаправляет переменные в lego как есть.
:::

## Настройка Private Key

<Steps>

1. Переходим в раздел `Private Keys` и нажимаем `New Key`.

2. В `Name` вводим название ключа (например, `ACME`).

3. `Key Generation Algorithm` указываем `ECDSA P-384` (рекомендуемый алгоритм для высокой безопасности и совместимости).

4. Ставим галочку на `Disable API Key`.

5. Нажимаем `Submit`.

6. Откроется окно с Private Key, в нём тоже нажимаем `Submit`.

## Настройка ACME Accounts

<Steps>

1. Переходим в раздел `ACME Accounts` и нажимаем `New Account`.

2. В поле `Name` вводим название нашего домена или другое название.

3. В поле `Contact E-mail Address` указываем email для уведомлений.

4. В поле `ACME Server` выбираем `Let’s Encrypt`.

5. В поле `Private Key` выбираем ранее созданный ключ.

6. Ставим галочку на `Accept ACME Server's Terms of Service`.

7. Нажимаем `Submit`.

8. Откроется окно с данными аккаунта:

    <div style={{ display: 'flex', justifyContent: 'center' }}>

        src="https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_acme_accounts.png"

## Настройка Certificates

<Steps>

1. Переходим в раздел `Certificates` и нажимаем `New Certificate`.

2. В поле `Name` вводим название нашего домена или другое название.

3. В поле `ACME Account` выбираем ранее созданный аккаунт.

4. В поле `Subject (and Common Name)` вводим домен 2 уровня, например `example.com`.

5. Нажимаем кнопку `ADD` и в поле `Alternate Name 1` вводим wildcard-домен `*.example.com`.

6. Нажимаем `Submit`.

    <div style={{ display: 'flex', justifyContent: 'center' }}>
      <img
        src="https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_certificates.png"
        alt="Cert Warden New Certificate"
        style={{ maxWidth: '60%' }}
      />

7. Внизу появится окно `ACME Orders`:

      ![Cert Warden ACME Orders](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_acme_orders.png)

## Cert Warden Client

Клиент Cert Warden работает как Docker-контейнер: забирает сертификаты с сервера по API-ключам, сохраняет файлы на диск и перезапускает указанные контейнеры, чтобы сервисы подхватили обновление.

:::tip[Панель за Caddy]
Если панель стоит за Caddy, отдельные файлы сертификатов ей не нужны: Caddy получает и продлевает их сам. Клиент Cert Warden тогда нужен остальным сервисам с файловыми сертификатами, например nginx нод.
:::

## Клиент на сервере панели Remnawave

<Steps>

1. Создаём директорию для клиента:

    ```bash
    mkdir -p /opt/certwardenclient/certs && cd /opt/certwardenclient && nano docker-compose.yml
    ```

    Вставляем следующее содержимое:

    ```yaml title="docker-compose.yml" "pLZEc_QvSka8syfQtuTfArblalMKU6C6Ke1uIji0E5g" "https://certwarden.example.com" "example.com" "0UkmZEZK7oieQ6hmz9Fta2obMMZRjAuo" "MkYMf7eXO8aB9xiNKqwvNVcDGKJ0Dg6v"
    services:
        certwardenclient:
          image: ghcr.io/gregtwallace/certwarden-client:latest
          container_name: certwardenclient
          restart: unless-stopped
          ports:
            - '127.0.0.1:5055:5055'
          volumes:
            - /var/run/docker.sock:/var/run/docker.sock
            - /opt/certwardenclient/certs:/opt/certwarden/certs
          environment:
            TZ: "Europe/Moscow"
            CW_CLIENT_FILE_UPDATE_TIME_START: "02:00"
            CW_CLIENT_FILE_UPDATE_TIME_END: "03:00"
            CW_CLIENT_FILE_UPDATE_DAYS_OF_WEEK: "Mon Tue Wed Thu Fri Sat Sun"
            CW_CLIENT_RESTART_DOCKER_CONTAINER0: "remnawave-nginx"
            CW_CLIENT_AES_KEY_BASE64: "pLZEc_QvSka8syfQtuTfArblalMKU6C6Ke1uIji0E5g"
            CW_CLIENT_SERVER_ADDRESS: "https://certwarden.example.com"
            CW_CLIENT_KEY_NAME: "example.com"
            CW_CLIENT_KEY_APIKEY: "0UkmZEZK7oieQ6hmz9Fta2obMMZRjAuo"
            CW_CLIENT_CERT_NAME: "example.com"
            CW_CLIENT_CERT_APIKEY: "MkYMf7eXO8aB9xiNKqwvNVcDGKJ0Dg6v"
            CW_CLIENT_CERT_PATH: "/opt/certwarden/certs"
            CW_CLIENT_KEY_PEM_FILENAME: "privkey.pem"
            CW_CLIENT_CERTCHAIN_PEM_FILENAME: "fullchain.pem"
          networks:
            - remnawave-network
          logging:
            driver: 'json-file'
            options:
              max-size: '30m'
              max-file: '5'

    networks:
        remnawave-network:
          name: remnawave-network
          driver: bridge
          external: true
    ```

    В `CW_CLIENT_RESTART_DOCKER_CONTAINER0` указан `remnawave-nginx`. Для панели за Caddy это `remnawave-caddy`.

2. `CW_CLIENT_AES_KEY_BASE64` это ключ из раздела `Certificates` → `Post Processing` → `Client AES Key`. Нажмите кнопку `GENERATE`, чтобы получить его.

    <div style={{ display: 'flex', justifyContent: 'center' }}>
      <img
        src="https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/refs/heads/main/docs/src/assets/en/certwarden/certwarden_aes_key.png"
        alt="Cert Warden AES Key"
        style={{ maxWidth: '50%' }}
      />
    </div>

3. `CW_CLIENT_SERVER_ADDRESS` это адрес сервера Cert Warden (например, `https://certwarden.example.com`).

4. `CW_CLIENT_KEY_NAME` это название ключа из раздела `Private Keys`.

5. `CW_CLIENT_KEY_APIKEY` это API-ключ из раздела `Private Keys`.

6. `CW_CLIENT_CERT_NAME` это название сертификата из раздела `Certificates`.

7. `CW_CLIENT_CERT_APIKEY` это API-ключ из раздела `Certificates`.

8. Запускаем клиент:

    ```bash
    cd /opt/certwardenclient && docker compose up -d && docker compose logs -f
    ```

9. В папке `/opt/certwardenclient/certs` должны появиться файлы `fullchain.pem` и `privkey.pem`.

10. Монтируем их в `docker-compose.yml` панели:

    ```bash
    cd /opt/remnawave && nano docker-compose.yml
    ```

    Добавляем в volumes, не забудьте указать ваш домен:

    ```yaml title="docker-compose.yml" "yourdomain.com"
    volumes:
      - /opt/certwardenclient/certs/fullchain.pem:/etc/nginx/ssl/yourdomain.com/fullchain.pem
      - /opt/certwardenclient/certs/privkey.pem:/etc/nginx/ssl/yourdomain.com/privkey.pem
    ```

11. Перезапускаем nginx:

    ```bash
    cd /opt/remnawave && docker compose down remnawave-nginx && docker compose up -d remnawave-nginx
    ```

</Steps>

## Клиент на сервере ноды Remnawave

:::note
Аналогично ставится и на другие ноды, которые будут получать сертификаты от Cert Warden. Обойтись без клиента можно: на сервере ноды сертификаты умеет выпускать и продлевать сам скрипт (пункт `10`, «Обновить текущие сертификаты»), а при добавлении ноды через меню сертификаты разворачиваются автоматически. Клиент Cert Warden нужен, только если вы хотите раздавать все сертификаты из одного места.
:::

2. `CW_CLIENT_AES_KEY_BASE64` это ключ из раздела `Certificates` → `Post Processing` → `Client AES Key`. Нажмите кнопку `GENERATE`, чтобы получить его.

3. `CW_CLIENT_SERVER_ADDRESS` это адрес сервера Cert Warden.

4. `CW_CLIENT_KEY_NAME` и `CW_CLIENT_KEY_APIKEY` это название и API-ключ из раздела `Private Keys`.

5. `CW_CLIENT_CERT_NAME` и `CW_CLIENT_CERT_APIKEY` это название и API-ключ из раздела `Certificates`.

6. Запускаем клиент:

    ```bash
    cd /opt/certwardenclient && docker compose up -d && docker compose logs -f
    ```

7. В папке `/opt/certwardenclient/certs` должны появиться файлы `fullchain.pem` и `privkey.pem`.

8. Монтируем их в `docker-compose.yml` ноды (её веб-сервер тоже называется `remnawave-nginx`):

    ```bash
    cd /opt/remnanode && nano docker-compose.yml
    ```

    ```yaml title="docker-compose.yml" "yourdomain.com"
    volumes:
      - /opt/certwardenclient/certs/fullchain.pem:/etc/nginx/ssl/yourdomain.com/fullchain.pem
      - /opt/certwardenclient/certs/privkey.pem:/etc/nginx/ssl/yourdomain.com/privkey.pem
    ```

9. Перезапускаем nginx ноды:

    ```bash
    cd /opt/remnanode && docker compose down remnawave-nginx && docker compose up -d remnawave-nginx
    ```

</Steps>

Если хотите закрыть доступ к Cert Warden с помощью NetBird, следуйте этим шагам.

</Steps>
