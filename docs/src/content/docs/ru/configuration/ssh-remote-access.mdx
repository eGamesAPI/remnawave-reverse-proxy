Модуль SSH-доступа позволяет обслуживать второй сервер (например, сервер с нодой) прямо из меню скрипта на панели: обновить пакеты, перезапустить контейнер ноды, посмотреть логи, не открывая вторую SSH-сессию. Другой модуль, [серверный роутинг](/ru/configuration/server-routing/), использует этот доступ автоматически, когда ставит ноду на второй сервер.

- **Пароль спрашивается один раз.** Скрипт установит свой ключ и забудет пароль: на диск он не пишется никогда.
- **Ваш ключ не читается.** Собственный ключ используется по пути, содержимое не копируется и не открывается.
- **Одна строка в `authorized_keys`.** Ключ скрипта живёт отдельной строкой с пометкой `remnawave-reverse-proxy`, ваши строки не трогаются.

Пункт находится в меню скрипта: **4. Расширения ноды → SSH-доступ к удалённому серверу**.

## Как это работает

<SshDiagram lang="ru" />

Сервер панели хранит список целей (ноды, известные панели, или адреса, введённые вручную) и ssh-ключи. При настройке скрипт один раз ставит свой ключ на цель по паролю, дальше пароль не нужен. Все операции ходят по ключу: выполнение команд, обновление ноды и настройка серверов выхода для [серверного роутинга](/ru/configuration/server-routing/).

## Первая настройка

<Steps>

1. **Выберите адрес сервера.** Сначала скрипт спросит адрес руками, а если панель уже знает ноды, покажет их списком, чтобы выбрать готовый адрес:

    <Terminal title="root@server: ~" lines={[
      { kind: 'plain', text: 'Адрес сервера (IP или домен): ', answer: '203.0.113.20' },
      { kind: 'plain' },
      { kind: 'title', text: 'Ноды, известные панели' },
      { kind: 'plain' },
      { kind: 'item', num: '1.', text: 'node.example.com ', warn: '(node-kazan)' },
      { kind: 'item', num: '2.', text: 'Ввести адрес вручную' },
    ]} />

2. **Порт, пользователь и подпись.** Порт и пользователя можно оставить по умолчанию, Enter подставит `22` и `root`. Подпись это название сервера в списке:

    <Terminal title="root@server: ~" lines={[
      { kind: 'plain', text: 'Порт SSH (Enter подставит 22): ', answer: '22' },
      { kind: 'plain', text: 'Пользователь SSH (Enter подставит root): ', answer: 'root' },
      { kind: 'plain', text: 'Подпись сервера в списке SSH-подключений (Enter - без подписи): ', answer: 'Kazan' },
    ]} />

3. **Проба существующих ключей.** Если на этом сервере уже есть ключ, который открывает второй сервер, скрипт молча возьмёт его: вопросы не задаются, на удалённом сервере ничего не меняется. Если не подошёл ни один, предложит четыре пути:

    <Terminal title="root@server: ~" lines={[
      { kind: 'step', text: 'Пробуем ключи, которые уже есть на этом сервере...' },
      { kind: 'err', text: 'Ни один существующий ключ не подошёл' },
      { kind: 'plain' },
      { kind: 'title', text: 'Ключ не сработал, выберите, как продолжить:' },
      { kind: 'plain' },
      { kind: 'item', num: '1.', text: 'Указать существующий ключ на этом сервере' },
      { kind: 'dim', text: '   файл используется на месте, содержимое не читается' },
      { kind: 'item', num: '2.', text: 'Ввести пароль root один раз' },
      { kind: 'dim', text: '   нужен только чтобы поставить наш ключ, потом забывается' },
      { kind: 'item', num: '3.', text: 'Показать наш публичный ключ для ручной установки' },
      { kind: 'dim', text: '   для серверов, где парольный вход закрыт' },
      { kind: 'plain' },
      { kind: 'input', text: 'Выберите действие (1-3):' },
    ]} />

    - **Свой ключ**: укажите путь до него, файл используется на месте.
    - **Пароль root один раз**: скрипт спросит пароль (ввод скрыт), установит свой отдельный ключ и забудет его.
    - **Ручная вставка**: для серверов с закрытым парольным входом скрипт покажет свой публичный ключ и команду, которую нужно выполнить на втором сервере. Проверка результата повторяется по <Kbd windows="Enter" />, выход из ожидания клавишей <Kbd windows="Q" />.

4. **Установка ключа паролем** выглядит так:

    <Terminal title="root@server: ~" lines={[
      { kind: 'plain', text: 'Пароль root от 203.0.113.20 (ввод скрыт): ' },
      { kind: 'step', text: 'Устанавливаем наш ключ на 203.0.113.20...' },
      { kind: 'ok', text: 'Ключ установлен, пароль больше не нужен' },
      { kind: 'plain' },
      { kind: 'ok', text: 'Доступ сохранён: root@203.0.113.20:22' },
    ]} />

</Steps>

:::tip[Проверка после настройки]
Модуль сразу предлагает проверить соединение и показать hostname удалённого сервера:

<Terminal title="root@server: ~" lines={[
  { kind: 'ok', text: 'Соединение работает (удалённый сервер: node-kazan)' },

Если увидели его, доступ работает.
:::

## Выполнение команд

Пункт «Выполнить команду» запускает команду на удалённом сервере, вывод приходит в терминал, в конце скрипт покажет код завершения:

<Terminal title="root@server: ~" lines={[
  { kind: 'plain', text: 'Команда для root@203.0.113.20:22: ', answer: 'docker logs remnanode --tail 5' },
  { kind: 'dim', text: '… вывод команды …' },
  { kind: 'ok', text: 'Команда выполнена (код 0)' },
  { kind: 'dim', text: 'Enter возвращает в меню...' },
]} />

Типовые сценарии:

```bash title="Обновление пакетов на удалённом сервере"
apt update && apt upgrade -y
```

```bash title="Обновление ноды (команды стартуют в /root, compose нужен cd)"
cd /opt/remnanode && docker compose pull && docker compose up -d
```

```bash title="Логи ноды"
docker logs remnanode --tail 50
```

:::note[Ограничения]
Интерактивные программы (`top`, `nano`, `mc`) не заработают: терминал на удалённую сторону не выделяется. Для просмотра состояния используйте обычные команды с текстовым выводом: `docker logs`, `free -h`, `df -h`.
:::

<details>
<summary><strong>Под капотом: где это хранится</strong></summary>

Все данные доступа лежат на панели в `/usr/local/remnawave_reverse`:

<FileTree>
- /usr/local/remnawave_reverse
  - remote-exec
    - **203.0.113.20_22.target** (сервер: адрес, порт, пользователь, ключ, название)
    - 203.0.113.5_22.target
  - remote-exec.active (какой сервер использовался последним)
  - ssh
    - id_ed25519 (ключ скрипта, один на все серверы)
    - known_hosts
</FileTree>

Файлы `.target` обычные `key=value`, правятся вручную только в крайнем случае: меню переименования и перенастройки делает то же самое безопаснее.

</details>
