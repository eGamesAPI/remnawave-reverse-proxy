## Данные подключения

Логин и пароль скрипт генерирует случайными и записывает в `.env` панели:

```bash title=".env" "gjlToiPH" "VsCNutHF"
### PROMETHEUS ###
### Metrics are available at http://127.0.0.1:METRICS_PORT/metrics
METRICS_USER=gjlToiPH
METRICS_PASS=VsCNutHF
```

Файл лежит в `/opt/remnawave/.env`, значения подтягиваются контейнером панели автоматически.

| Переменная | Назначение | Значение у скрипта |
| :-- | :-- | :-- |
| `APP_PORT` | Порт панели | `3000` (только внутри Docker) |
| `METRICS_PORT` | Порт метрик | `3001`, привязан к `127.0.0.1` |
| `METRICS_USER` | Логин для метрик | случайный |
| `METRICS_PASS` | Пароль для метрик | случайный |
| `APP_SECRET` | Ключ подписи сессий и API-токенов | случайный |

:::note[Если панель ставилась без скрипта]
В оригинальной установке Remnawave значения по умолчанию `admin` и `change_me`. Обязательно смените их перед использованием метрик.
:::

## Быстрая проверка

На самом сервере метрики можно получить одной командой (ответ в текстовом формате Prometheus):

```bash "gjlToiPH" "VsCNutHF"
curl -u gjlToiPH:VsCNutHF http://127.0.0.1:3001/metrics | head
```

С своего компьютера эндпоинт можно посмотреть через SSH-туннель, не открывая порт наружу:

```bash
ssh -L 3001:127.0.0.1:3001 root@your_server_ip
```

После этого `http://127.0.0.1:3001/metrics` доступен и в локальном браузере.

## Настройка сборщика

Забирать метрики нужно с самого сервера, прямо с `127.0.0.1`. Конфиг для vmagent (его использует руководство по мониторингу):

```yaml title="vmagent/conf.d/remnawave.yml" "ваше_название_инстанса"
- job_name: remnawave
  scrape_interval: 15s
  static_configs:
    - targets: ['127.0.0.1:3001']
      labels:
        instance: "ваше_название_инстанса"
  basic_auth:
    username: "gjlToiPH"
    password: "VsCNutHF"
```

Для классического Prometheus секция выглядит так же:

```yaml title="prometheus.yml"
scrape_configs:
  - job_name: 'remnawave'
    scheme: http
    metrics_path: /metrics
    scrape_interval: 15s
    static_configs:
      - targets: ['127.0.0.1:3001']
    basic_auth:
      username: gjlToiPH
      password: VsCNutHF
```

:::tip
Полное руководство по мониторингу: Victoria Metrics для хранения, Grafana для дашбордов, node_exporter и cAdvisor для серверов.
:::

## Почему снаружи метрики не видны

Скрипт публикует порт метрик только на localhost:

```yaml title="docker-compose.yml"
ports:
  - '127.0.0.1:3001:3001'
```

Поэтому прямое обращение извне невозможно, и это не обходится настройкой cookie, как у страницы входа в панель: у метрик своя защита (привязка порта + basic auth). Забрать метрики снаружи можно двумя способами: агент на самом сервере (vmagent/Prometheus с `remote_write`) или SSH-туннель, как выше.

:::note[Метрики Xray Checker]
Если установлен модуль Xray Checker, его метрики живут отдельно, на `http://127.0.0.1:2112/metrics` (доступ с сервера или по SSH-туннелю), и собираются они тем же способом.
:::
