Он снимает резервную копию всей панели Remnawave: базу PostgreSQL и директорию установки со всеми конфигурациями. Старые копии подчищаются сами по политике хранения.

## Что попадает в копию

- **База данных.** В режиме Docker дамп снимается командой `pg_dumpall` прямо внутри контейнера `remnawave-db`, поэтому в копию попадает и база, и роли с глобальными настройками. Для внешней PostgreSQL инструмент поднимает одноразовый контейнер `postgres` и снимает дамп по сети, SSL-режим настраивается.
- **Директория панели.** Архивируется целиком, кроме временных файлов: `*.log`, `*.tmp` и `.git` исключаются.
- **Telegram-бот магазина (опционально).** Если включён бэкап бота, его база и директория добавляются в тот же архив.

Всё складывается в один файл вида `remnawave_backup_full_2026-10-04_12_00_00.tar.gz`. Слово в имени (`full`, `panel`, `bot`) сразу показывает состав. Внутри архива дамп базы, архив директории и файл `backup_meta.info` с версией панели, версией скрипта и типом дампа: при восстановлении инструмент сверяет эти данные с текущим режимом и предупредит о несовпадении.

Несколько деталей поведения:

- Файл всегда остаётся на сервере в `/opt/rw-backup-restore/backup`, отправка в Telegram или облако происходит дополнительно.
- Telegram не принимает файлы больше 50 МБ: такой бэкап остаётся только локально, а в чат приходит уведомление о превышении лимита.
- Политика хранения по умолчанию держит локальные копии 7 дней, в S3 отдельно настраивается 30 дней.
- После отправки инструмент проверяет обновление самого себя и при наличии свежей версии присылает уведомление в Telegram.

Если в архиве нашёлся бэкап магазина, следом инструмент предложит восстановить и его, предварительно предупредив: бот, запущенный на другом сервере, нужно остановить, иначе два экземпляра начнут конфликтовать.

:::note[Восстановление из S3]
Источник `Скачать из S3 Storage` показывает список копий прямо из бакета и восстанавливает потоком, не сохраняя файл на диск: это удобно на серверах с маленьким свободным местом.
:::

## Переезд на новый сервер

Копия переносит панель целиком, поэтому для переезда достаточно восстановить её на новом сервере и поправить окружение:

1. В Cloudflare смените IP поддомена панели (и поддомены остальных сервисов, если они переезжают вместе с ней).
2. Восстановите директорию и базу из копии, как описано выше.
3. Ссылка доступа и пароль панели останутся от старого сервера: их трогать не нужно.
4. Если сервисный порт панели (по умолчанию 2222) на нодах открыт только для старого адреса, замените правило на каждой ноде:

```bash
ufw delete allow from OLD_IP to any port 2222 && ufw allow from NEW_IP to any port 2222
```

При переезде связки «панель и нода на одном сервере» дополнительно поменяйте адрес корневой ноды в управлении нодами панели: она активируется сама. Сертификаты для домена восстанавливаются отдельно, например через Certwarden или пункт «Управление сертификатами домена» главного меню.

## Файлы и пути

- `/opt/rw-backup-restore`: каталог установки, внутри скрипт, `config.env` с настройками и переводы.
- `/opt/rw-backup-restore/backup`: склад готовых копий, отсюда же идёт восстановление.
- `/opt/rw-backup-restore-saved`: сюда сохраняются копии при удалении инструмента.

:::note[Команды без меню]
Установленный скрипт принимает аргументы: `rw-backup backup`, `rw-backup restore`, `rw-backup update` и `rw-backup remove` выполняют соответствующие действия сразу, без главного меню.
:::
