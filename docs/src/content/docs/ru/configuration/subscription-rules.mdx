Правила ответов решают, что панель отдаёт на каждый запрос подписки. Приложению клиента нужен конфиг, браузеру достаточно красивой страницы, а чужому скрипту, который перебирает украденные ссылки, лучше всего получить 404 и уйти ни с чем. Модуль показывает текущее состояние одним экраном, применяет готовые наборы правил и включает привязку подписки к устройствам. Всё меняется через API панели, конфиги вручную править не нужно.

## Как это устроено

Панель оценивает каждый запрос подписки по заголовкам: какое приложение его прислало и с какого устройства. Правило состоит из условий по заголовкам и типа ответа. Правила проверяются по порядку сверху вниз, срабатывает первое подходящее, и его тип ответа уходит клиенту.

<SubscriptionRulesDiagram lang="ru" />

Привязка устройств работает рядом с правилами. Happ и INCY передают панели заголовок `x-hwid` с идентификатором устройства. Когда лимит включён, подписка выдаётся не больше чем N устройствам одного пользователя, остальные получают вежливое сообщение вместо конфигов. Список занятых мест виден в карточке пользователя в панели, потерянное устройство оттуда можно удалить и освободить слот. Отдельным пользователям лимит можно поменять или отключить персонально, это делается в панели.

Всё хранится в панели, те же настройки доступны в её веб-интерфейсе в разделе подписок. Модуль лишь удобная обёртка: меняет значения через API, показывает результат и хранит копии. Если вы пользуетесь внешними группами панели, учтите, что правила ответов главнее их настроек.

:::note[Панель 3.4 и новее]
Свежие версии панели отвечают 403 на запросы подписки, пока правила не настроены. Если после обновления панели подписки внезапно перестали открываться, примените любой набор правил из этого модуля, и всё вернётся на место.
:::

## Что панель может отдать

Тип ответа в правиле решает, что именно получит клиент. Наборы правил модуля используют часть типов, свои правила в панели можно собрать из полного списка.

| Тип ответа | Что получает клиент |
|---|---|
| Xray JSON | Полный конфиг Xray одним файлом, с правилами маршрутизации. Так работают Happ, INCY и v2rayN |
| Base64 | Базовый список серверов в кодировке Base64. Его понимает любое приложение, это безопасный выбор по умолчанию |
| Mihomo, Clash, Stash, Sing-box | Конфиг в формате конкретного семейства клиентов |
| Страница в браузере | HTML-страница подписки со списком серверов и инструкциями |
| Блок 403, 404, 451 | Пустой отказ. Для чужих запросов 404 выглядит естественнее всего: будто по этому адресу ничего и не было |
| Обрыв соединения | Панель молча разрывает соединение, без кода ответа |

## Строгий пресет

Пресет «Строгий: Happ и INCY + устройства» рассчитан на продажу подписок. Он отдаёт конфиги только проверенным запросам, а всем остальным возвращает 404. Набор правил выглядит так:

| Кто спрашивает | Условие | Что получает |
|---|---|---|
| Happ и INCY | `user-agent` начинается с `Happ/` или `INCY/`, есть корректный `x-hwid` | Полный конфиг Xray JSON |
| Клиенты Clash | `user-agent` начинается с `FlClashX/`, `koala-clash/`, `prizrak-box/`, `rabbithole/`, `clash-mi/` или `ClodClash/`, есть корректный `x-hwid` | Конфиг Mihomo под ядро Clash |
| Karing и InHive | `user-agent` начинается с `Karing/` или `InHive/`, есть корректный `x-hwid` | Конфиг Sing-box |
| Известные приложения | `user-agent` начинается с названия из списка: v2rayN, v2rayNG, V2Box, Streisand, sing-box, Karing, FlClash, Flowvy, prizrak-box, Koala Clash, Clod Clash, sfa, sfi, sfm, sft, rabbithole | Список Base64 |
| Открытие в браузере | заголовок `accept` содержит `text/html` | Страницу подписки |
| Встроенный браузер | `user-agent` содержит YaSearchBrowser, HuaweiBrowser, SamsungBrowser, MiuiBrowser, UCBrowser, QQBrowser, Quark | Страницу подписки |
| Браузер | `user-agent` содержит Mozilla, AppleWebKit, Gecko, Chrome, Chromium, Safari, Firefox, CriOS, FxiOS, Edg, OPR, YaBrowser, Vivaldi и другие движки | Страницу подписки |
| Все остальные | условий нет | 404 |

Первое браузерное правило смотрит не на User-Agent, а на сам запрос: когда браузер переходит по ссылке подписки, он просит HTML-страницу. Так страница открывается даже в браузерах с сокращённым или подменённым User-Agent, включая встроенные браузеры Яндекс, Huawei, Samsung и Xiaomi, а два правила по User-Agent страхуют остальные случаи.

Строгий пресет имеет смысл включать вместе с лимитом устройств: тогда украденная ссылка бесполезна даже с подменённым названием приложения, потому что чужое устройство не пройдёт лимит. Клиенты Clash и Sing-box, RenoarX, Happ и INCY сообщают панели идентификатор устройства: со включённым лимитом они проходят проверку и получают конфиг в своём формате.

:::danger[Важно]
После строгого пресета приложения не из списка, например Hiddify, Clash Verge или NekoBox, получат 404. Сразу проверьте подписку на собственном устройстве. Не подошло: верните «Клиенты и браузеры» или восстановите сохранённую копию.
:::

      { kind: 'ok', text: 'Лимит устройств включён: до 3 на пользователя' },

Что панель знает об устройстве:

| Заголовок | Что содержит | Пример |
|---|---|---|
| `x-hwid` | Идентификатор устройства, обязательный для лимита | `UE42LJXu4DbiCaBv` |
| `x-device-os` | Система устройства | `iOS` или `Android` |
| `x-ver-os` | Версия системы | `18.3` |
| `x-device-model` | Модель устройства | `iPhone 14 Pro Max` |

Happ, INCY, RenoarX, DeskBox, v2RayTun, Flowvy, Clod Clash и клиенты Clash присылают эти заголовки сами. Throne, Shadowrocket, Clash Mi и Karing тоже поддерживают привязку, но шлют заголовок только после её включения в настройках приложения. Без заголовка остаются v2rayN, v2rayNG, FlClash, Stash и официальный sing-box: с включённым лимитом их владельцы подписку не получат. Такому пользователю лимит отключается персонально в карточке в панели, на остальных ограничение продолжит действовать.

Лимит считается по разным устройствам. Если пользователь сменил телефон и старый занимает слот, лишнее устройство удаляется из списка в карточке, и новое сразу проходит.
