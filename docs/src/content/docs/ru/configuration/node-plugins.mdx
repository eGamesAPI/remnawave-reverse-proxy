Все три функции живут в одной записи плагина `Reverse Node Plugins`, настраиваются через API панели с сервера, где панель установлена, и применяются на нодах без перезапусков.

## Как это устроено

<NodePluginsDiagram lang="ru" />

У каждой ноды Remnawave есть ровно один активный плагин (`activePluginUuid`), поэтому три функции не могут быть тремя отдельными записями: активной всегда была бы только одна. Скрипт держит одну общую запись с тремя секциями конфига: `torrentBlocker`, `ingressFilter` и `egressFilter`.

Каждое изменение настроек проходит один и тот же путь:

Оффлайн-ноды получают привязку в базе панели и подхватят конфиг при подключении.

В верхней части меню модуля всегда видна строка правды: `Нод под плагином: 2 из 2`. Плагин, на который не указывает ни одна нода, не работает, что бы ни показывали статусы функций.

:::note[Кэш панели]
API панели кэширует состояние плагинов на несколько секунд. Если сразу после включения меню показывает прежний статус, а в интерфейсе панели всё уже включено, значит работает, статус подтянется сам.
:::

## Что понадобится

:::danger[Важно]
Плагины настраиваются через API панели, поэтому запускать модуль нужно на сервере, где установлена панель Remnawave. На сервере только с нодой пункт меню не появится.
:::

Для Torrent Blocker требуется Node версии 2.7.0 и новее с ядром Xray 26.3.27+.

При первом входе модуль проверяет, нет ли на аккаунте старых записей плагинов от прошлых версий скрипта (они назывались `Torrent Blocker`, `Ingress Filter`, `Egress Filter` по отдельности). Такие записи предлагается объединить в одну: настройки сольются, лишние записи удалятся, плагин привяжется ко всем нодам. Отказ ничего не меняет, вопрос повторится при следующем входе.

### Разблокировать IP

Если бан пришёлся на адрес, который трогать не хотели (например, пользователь за CGNAT, и под бан ушла вся подсеть провайдера), IP можно разблокировать сразу на всех нодах:

<Steps>

1. Выберите пункт `Разблокировать IP` и укажите адрес:

    <Terminal title="root@server: ~" lines={[
      { kind: 'plain', text: 'IP для разблокировки на всех нодах: ', answer: '185.220.101.5' },
      { kind: 'step', text: '[ * ] Разблокирую 185.220.101.5...' },
      { kind: 'ok', text: '[ ✓ ] Запрос на разблокировку 185.220.101.5 принят нодами.' },
    ]} />

</Steps>

Адрес под баном снова попадёт в блок-лист при следующем срабатывании. Чтобы вообще не блокировать его, добавьте IP в белый список в настройках.

### Пересоздать таблицы nftables

Пункт пересоздаёт nftables-таблицу плагина на всех нодах: сбрасывает активные баны и очищает таблицу от остатков после сбоев. Списки Ingress Filter и Egress Filter живут в той же таблице, поэтому если они включены, скрипт предупредит: после сброса ноды могут держать их пустыми до следующего изменения конфига плагина или перезапуска ноды.

<Steps>

## Ingress Filter

Фильтр блокирует входящие соединения на уровне nftables по списку подсетей: сканеры интернета стучатся в порт ноды и не получают ответа. Список один на все ноды, у каждой функции свой статус.

:::danger[Важно]
Пресеты режут целыми подсетями. Если хостер соседствует со сканерами в этих диапазонах, под бан могут попасть и его адреса: неактуальный для ваших нод пресет лучше не применять.
:::

## Egress Filter

Фильтр блокирует исходящий трафик сервера по адресам назначения и портам. Основной сценарий: сервер взломали через украденную учётную запись, и вредоносная программа пытается уйти в частные сети или разослать спам, а двери уже закрыты.

:::danger[Важно]
Фильтр действует на весь исходящий трафик сервера, а не только клиентов: не блокируйте адреса, которые нужны самому хосту (DNS, mesh VPN). Loopback не блокируйте, 127.0.0.0/8 в пресеты не входит.
:::

## Общий плагин и привязка к нодам

Несколько деталей, которые стоит знать про то, как модуль обращается с записями плагинов в панели:

- **Одна запись на всё.** Плагин называется `Reverse Node Plugins`, uuid сохраняется на сервере панели, поэтому переименование записи в интерфейсе панели его не теряет.
- **Привязка при каждом сохранении.** Сохранённый конфиг ничего не значит, пока плагин не активен на ноде. После каждого изменения модуль заново привязывает его ко всем включённым нодам и синхронизирует конфиг.
- **Чужой плагин на нодах.** Если часть нод держит активным другой плагин (свой кастомный), модуль спросит, перевязать ли и их. Отказ запоминается до конца сессии: такие ноды остаются на своём плагине, запись в панели не удаляется.

    <Terminal title="root@server: ~" lines={[
      { kind: 'input', text: 'На этих нодах активен другой плагин: us-nyc-03. Привязать и их к общему плагину? Их текущий плагин на них перестанет действовать (запись останется в панели) (y/n): ', answer: 'n' },
      { kind: 'step', text: 'Оставлены на своём плагине: us-nyc-03 — общий плагин на них не действует.' },
    ]} />

- **Объединение старых записей.** Записи, оставшиеся от прошлых версий скрипта, модуль при входе предлагает слить в одну: конфиги глубоко объединяются, списки адресов складываются без потерь, лишние записи удаляются.
