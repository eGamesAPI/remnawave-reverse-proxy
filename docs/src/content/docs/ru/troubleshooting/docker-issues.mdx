Здесь собраны две самые частые проблемы с загрузкой Docker-образов и их решения.

## Сервер не может скачать образы

На некоторых серверах, особенно в России, Docker Hub недоступен и образы не загружаются (пример в issue [#40](https://github.com/eGamesAPI/remnawave-reverse-proxy/issues/40)). Решение: зеркала реестра.

<Steps>

1. Создайте или откройте файл `daemon.json`:

    ```bash
    nano /etc/docker/daemon.json
    ```

2. Вставьте конфигурацию с зеркалами:

    ```json title="daemon.json"
    {
    "log-driver": "local",
    "registry-mirrors": [
        "https://mirror.gcr.io/",
        "https://dockerhub.timeweb.cloud"
        ]
    }
    ```

3. Перезапустите службу Docker:

    ```bash
    systemctl restart docker
    ```

4. Проверьте, что зеркала подхватились:

    ```bash
    docker info | grep -A 3 "Registry Mirrors"
    ```

</Steps>

## You have reached your unauthenticated pull rate limit

Такое сообщение означает, что исчерпан лимит загрузки образов для анонимных запросов к Docker Hub. Что можно сделать:

<Steps>

1. Войдите в Docker Hub:

    ```bash
    docker login
    ```

    Авторизованные запросы считают по аккаунту, а не по адресу сервера.

2. Смените внешний адрес сервера

    Лимит привязан к IP: если адрес динамический, поможет перезагрузка сервера, иначе спросите хостера о смене адреса.

3. Включите IPv6

    Запустите `remnawave_reverse`, выберите пункт `9` (`Управление IPv6`) и включите поддержку IPv6. Загрузка пойдёт с другого адреса, и лимит часто отпускает.

</Steps>
