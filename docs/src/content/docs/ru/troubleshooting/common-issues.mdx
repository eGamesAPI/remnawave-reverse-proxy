## Подключение ботов

Если вы развертываете бота рядом с панелью на том же сервере, укажите в его окружении режим `local` и адрес `http://remnawave:3000`: контейнер бота обращается к панели напрямую по внутренней сети Docker, и проблемы с внешним доступом отпадают.

Для ботов и сервисов вне сервера воспользуйтесь [руководством по внешнему доступу к API](../configuration/external-api/).

## Потерян секретный вход в панель

Вход в панель живёт в ссылке вида `https://panel.example.com/auth/login?ИМЯ=ЗНАЧЕНИЕ`. Если ссылка потеряна, её можно собрать заново из конфигурации nginx:

<Steps>

1. Откройте конфигурацию nginx панели:

    ```bash
    nano /opt/remnawave/nginx.conf
    ```

2. В самом начале файла нас ждёт секция про секретную ссылку: карта `map $arg_...` с вашей парой.

    ```nginx title="nginx.conf" "zIdejKtN=MWbLrRzx"
    map $arg_zIdejKtN $set_cookie_header {
        "MWbLrRzx" "zIdejKtN=MWbLrRzx; Path=/; HttpOnly; Secure; SameSite=Strict; Max-Age=31536000";
        default "";
    }
    ```

    Пару можно достать и одной командой:

    ```bash
    grep -A3 'map $arg_' /opt/remnawave/nginx.conf | head -6
    ```

3. Скопируйте пару `ИМЯ=ЗНАЧЕНИЕ` и подставьте её в ссылку для входа:

    ```bash "panel.example.com" "zIdejKtN" "MWbLrRzx"
    https://panel.example.com/auth/login?zIdejKtN=MWbLrRzx
    ```

</Steps>

## Алиас `rr` не работает в zsh или fish

Скрипт прописывает алиас `rr` в системный файл `/etc/bash.bashrc`, поэтому он сразу работает в bash. Оболочки zsh и fish этот файл не читают:

<Steps>

1. Откройте конфигурацию своей оболочки (для zsh):

    ```bash
    nano ~/.zshrc
    ```

2. Добавьте строку, которая подключит системные алиасы:

    ```bash
    source /etc/bash.bashrc
    ```

3. Примените изменения:

    ```bash
    exec zsh
    ```

</Steps>

:::tip
Полное имя команды `remnawave_reverse` работает в любой оболочке и без алиаса.
:::
