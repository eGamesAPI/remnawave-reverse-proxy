`Cloudflare Warp Native` is a way to use the Cloudflare Warp service over WireGuard in `native` mode: a direct WireGuard setup with no dependency on the official Cloudflare client (the 1.1.1.1 app or warp-cli). In wgcf terms, it means a generated WireGuard profile connected to the Cloudflare Warp infrastructure, usable in any WireGuard-compatible client.

The module builds on two open-source projects:

## What is Cloudflare Warp?

`Cloudflare Warp` is a service that routes user traffic through Cloudflare servers, providing:

- Security: traffic encryption to protect the data.
- Privacy: hiding the user's IP address.
- Optimization: routing through Cloudflare's global network for better speed and reliability.

## How it works

<WarpDiagram lang="en" />

From the panel server the module adds the `warp-out` outbound and a routing rule with the selected domains to the node's configuration profile. The node sends only those domains through the `warp` interface, everything else goes direct, and websites see a Cloudflare address instead of the server's own.

### Installing WARP Native

:::danger[Important]
WARP Native is installed only on a server that runs a RemnaWave node.
:::

<Steps>

1. Select `Install WARP Native`

    <Terminal title="root@server: ~" lines={[

2. The script downloads and runs the wgcf installer: before running, it is verified against checksums from two independent sources; on a mismatch the run is cancelled.

</Steps>

### Adding WARP settings

:::danger[Important]
Run only on the server with the RemnaWave panel installed.
:::

<Steps>

1. Select `Add WARP-configuration to node configuration` and confirm you are on the panel server:

    <Terminal title="root@server: ~" lines={[

If WARP is already configured, the module warns: "warp-out already exists in outbounds." Nothing is duplicated.

The following blocks are added to your node's configuration profile section:

export const exampleCode = `{
  "tag": "warp-out",
  "protocol": "freedom",
  "settings": {
    "domainStrategy": "UseIP"
  },
  "streamSettings": {
    "sockopt": {
      "interface": "warp",
      "tcpFastOpen": true
    }
  }
}`;
export const fileName = 'outbound';

### Removing WARP settings

The `Remove WARP-configuration from node configuration` item asks for the same node and takes the additions out:

<Terminal title="root@server: ~" lines={[
  { kind: 'title', text: 'Select node to remove WARP-configuration?' },
  { kind: 'plain' },
  { kind: 'item', num: '1.', text: 'Default-Profile ', warn: '(de-fra-01)' },
  { kind: 'plain' },
  { kind: 'input', text: 'Select action:' },
  { kind: 'plain' },
  { kind: 'ok', text: 'Removed warp-out from outbounds' },
  { kind: 'ok', text: 'Removed warp rule from routing rules' },
]} />

If the profile has no blocks left, the module says so directly: "warp-out not found in outbounds". The WireGuard interface itself is removed by the `Uninstall WARP Native` item, after which the module answers "WARP deleted successfully".
