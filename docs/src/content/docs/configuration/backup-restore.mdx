The `Backup and Restore` entry of the main menu wires in the `remnawave-backup-restore` tool by distillium. It takes a full copy of the Remnawave panel: the PostgreSQL database and the entire installation directory with all of its configuration. The copy can be restored on the same server or deployed on a new one, created manually or on a schedule, and delivered to Telegram, Google Drive or an S3-compatible storage. Old copies clean themselves up according to the retention policy.

## What goes into a copy

- **The database.** In Docker mode the dump is taken with `pg_dumpall` right inside the `remnawave-db` container, so roles and global settings land in the copy along with the data. For an external PostgreSQL the tool spins up a throwaway `postgres` container and dumps over the network, with a configurable SSL mode.
- **The panel directory.** Archived in full, minus temporary files: `*.log`, `*.tmp` and `.git` are excluded.
- **A Telegram shop bot (optional).** When bot backup is enabled, its database and directory are added to the same archive.

Everything is packed into a single file like `remnawave_backup_full_2026-10-04_12_00_00.tar.gz`. The word in the name (`full`, `panel`, `bot`) tells you the scope at a glance. Inside the archive sit the database dump, the directory archive and a `backup_meta.info` file with the panel version, the script version and the dump type: on restore the tool matches this data against the current mode and warns about a mismatch.

A few details about the behavior:

- The file always stays on the server in `/opt/rw-backup-restore/backup`, delivery to Telegram or cloud storage happens on top of that.

- By default the retention policy keeps local copies for 7 days, while S3 keeps its own configurable 30 days.
- After delivery the tool checks for updates to itself and sends a Telegram notification when a newer version is out.

- **Telegram** delivers the copy as a file to a chat or group topic. The limit is 50 MB, so larger panels are better off with cloud delivery.
- **Google Drive** requires creating a Google API app and obtaining a Client ID, Client Secret and Refresh Token: the tool walks you through, shows the authorization link and asks for the code from the browser. Copies land in the chosen Drive folder, while notifications still arrive in Telegram.
- **S3 Storage** works with any S3-compatible storage. You need an Endpoint URL, Region, bucket name, Access Key and Secret Key, plus an optional prefix (folder) and a retention period in days. AWS CLI is installed automatically, and the connection can be checked with a test in the settings.

When Google Drive or S3 setup is left unfinished, the tool does not stay silent: it falls back to Telegram and tells you about it.

## Moving to a new server

The copy carries the panel in full, so a migration boils down to restoring it on the new server and adjusting the pieces around it:

1. In Cloudflare change the IP of the panel subdomain (and of other services moving along with it).
2. Restore the directory and the database from the copy as described above.
3. The access link and the panel password stay the ones from the old server: no need to touch them.
4. If the panel was given a dedicated service port, the nodes must allow traffic from the new address. Replace the rule on every node:

```bash
ufw delete allow from OLD_IP to any port 2222 && ufw allow from NEW_IP to any port 2222
```

When moving a panel and a node that share one server, also update the address of the root node in the panel's node management: it activates on its own. Domain certificates are restored separately, for example via Certwarden or the "Manage certificates domain" entry of the main menu.

## Files and paths

- `/opt/rw-backup-restore`: the install directory holding the script, the `config.env` settings and the translations.
- `/opt/rw-backup-restore/backup`: the storage for finished copies and the place restore reads from.
- `/opt/rw-backup-restore-saved`: copies are preserved here when the tool is removed.

:::note[Commands without the menu]
The installed script accepts arguments: `rw-backup backup`, `rw-backup restore`, `rw-backup update` and `rw-backup remove` run the matching action immediately, skipping the main menu.
:::
