## Обзор

Скрипт устанавливает панель управления Remnawave, ноды Xray и страницу подписки, а после установки сам становится меню управления сервером: полтора десятка модулей, от правил подписок до резервных копий.

Обратный прокси поднимается на NGINX или Caddy. Архитектура рассчитана на скорость: Xray занимает порт 443 и передает трафик веб-серверу через Unix-сокет, без лишних сетевых переходов между ними.

| Версия | Системы | Веб-сервер | Права |
|:---:|:---:|:---:|:---:|
| 3.8.3 | Debian, Ubuntu | NGINX или Caddy | root |

> [!IMPORTANT]
> Скрипт тестировался в среде виртуализации KVM. Для работы нужен собственный домен. Рекомендуется запускать с правами root на свежеустановленной системе.

### Режимы развертывания

**1. Один сервер**
- Панель управления и нода Xray на одной машине
- Подходит для компактных установок с умеренным трафиком

**2. Распределенная установка**
- **Сервер панели**: центр управления без ноды Xray
- **Сервер ноды**: нода Xray с заглушкой SelfSteal для VLESS REALITY

Варианты установки: панель с нодой, панель со страницей подписки, отдельная панель, отдельная нода, отдельная страница подписки, а также подключение еще одной ноды к работающей панели.

### Требования к доменам

Подготовьте три домена или поддомена:

1. **Панель управления**: доступ к интерфейсу управления
2. **Страница подписки**: раздача конфигураций клиентам
3. **Заглушка SelfSteal**: маскировочный сайт на сервере ноды

## Модули

### Установка и обслуживание

| Модуль | Что делает |
|---|---|
| Установка компонентов | Пять режимов установки и подключение новой ноды к работающей панели |
| Управление панелью | Статус служб, запуск и остановка, обновление, логи, Remnawave CLI, доступ к панели |
| Резервные копии и восстановление | Копия базы PostgreSQL и конфигураций панели, восстановление на том же или новом сервере, отправка в Telegram, Google Drive и S3, копирование по расписанию |
| Обновление скрипта | Проверка и установка обновлений, запуск сокращенной командой `rr` |

### Расширения ноды

| Модуль | Что делает |
|---|---|
| Шаблон SelfSteal | Маскировка ноды под обычный сайт, выбор из набора шаблонов |
| Node Plugins | Плагины ноды через панель, например Torrent Blocker |
| Xray core | Свежее ядро Xray вместо штатного |
| SSH-доступ к удаленным серверам | Список сохраненных серверов и запуск команд на них |
| Маршрутизация | Направление выбранных доменов через сервер выхода, остальной трафик идет напрямую |
| Балансировщик клиентов | Одна запись в подписке вместо списка хостов, клиент автоматически переключается на рабочий |

### Подписки

| Модуль | Что делает |
|---|---|
| Правила подписок и ответов | Пресеты правил панели: какие клиенты какие конфигурации получают, лимит устройств, JSON и дополнительные пути |
| Страница подписки | Шаблон Orion вместо штатной страницы и обратный переход |

### Сеть и сертификаты

| Модуль | Что делает |

| Управление IPv6 | Включение и отключение IPv6 на сервере |

## Настройка доменов

Сертификаты выпускаются одним из способов:

- **DNS API**: Cloudflare, Gcore или Bunny.net. Выпуск wildcard-сертификата, DNS-записи создаются автоматически по API-ключу
- **ACME HTTP-01**: без API-ключа, по одному домену на сертификат
- **Собственные сертификаты**: уже выпущенные на вашем сервере, продление вручную

<details>
<summary><b>Примеры настройки DNS</b></summary>

#### Установка на одном сервере (панель + нода вместе)

| Тип записи | Имя               | Значение         | Статус прокси |
|------------|-------------------|------------------|---------------|
| A          | example.com       | your_server_ip   | DNS only      |
| CNAME      | panel.example.com | example.com      | DNS only      |
| CNAME      | sub.example.com   | example.com      | DNS only      |
| CNAME      | node.example.com  | example.com      | DNS only      |

> [!TIP]
> Запись `node.example.com` является необязательной для функциональности SelfSteal. Вы можете использовать корневой домен `example.com` вместо нее.

#### Распределенная установка (панель и нода на разных серверах)

| Тип записи | Имя               | Значение                | Статус прокси |
|------------|-------------------|-------------------------|---------------|
| A          | example.com       | panel_server_ip         | DNS only      |
| CNAME      | panel.example.com | example.com             | DNS only      |
| CNAME      | sub.example.com   | example.com             | DNS only      |
| A          | node.example.com  | node_server_ip          | DNS only      |

</details>

## Руководство по установке

По ходу установки скрипт спросит язык интерфейса, веб-сервер (NGINX или Caddy), способ выпуска сертификатов, вариант защиты панели и данные доменов.

<details>
<summary><b>Развертывание на одном сервере</b></summary>

1. Запустите скрипт установки
2. Выберите **"Установка компонентов Remnawave"**
3. Выберите **"Установить панель и ноду на один сервер"**
4. Дождитесь завершения
5. Скрипт автоматически перезапустит сервисы и отобразит учетные данные для входа

</details>

<details>
<summary><b>Распределенное развертывание (панель и нода на разных серверах)</b></summary>

**Шаг 1: Настройка сервера панели**

1. Запустите скрипт установки на первом сервере
2. Выберите **"Установка компонентов Remnawave"**
3. Выберите **"Установить только панель"**
4. Сохраните предоставленные учетные данные

**Шаг 2: Экспорт ключа ноды**

1. Войдите в панель управления
2. Перейдите в **Ноды** → **Управление**
3. Выберите целевую ноду
4. Найдите поле **"Secret Key (SECRET_KEY)"**
5. Скопируйте значение с помощью иконки копирования

**Шаг 3: Настройка сервера ноды**

1. Запустите скрипт установки на втором сервере
2. Выберите **"Установка компонентов Remnawave"**
3. Выберите **"Установить только ноду"**
4. Вставьте ключ при запросе
5. Дождитесь сообщения об успешном подключении ноды

</details>

## Безопасность

### Защита доступа к панели

При установке на NGINX панель закрывается секретной ссылкой с cookie (по умолчанию) или страницей входа TinyAuth. При установке на Caddy доступен третий вариант: страница входа с многофакторной аутентификацией.

Секретная ссылка выглядит так:

```
https://panel.example.com/auth/login?<SECRET_KEY>=<SECRET_KEY>
```

Как это работает:

1. Переход по ссылке с правильным параметром устанавливает в браузере cookie: имя и значение совпадают с `<SECRET_KEY>`
2. Панель открывается только при наличии правильной cookie
3. Без параметра и без cookie сканер увидит пустую страницу или ошибку 404

Такая схема прячет панель от сканирования хостов, подбора путей и попыток брутфорса.

### На уровне сервера

- **Брандмауэр**: UFW открывает только необходимые порты
- **TCP**: алгоритм контроля перегрузки BBR
- **Маскировка**: заглушка SelfSteal со случайным шаблоном сайта
- **Сеть панель-нода**: трафик внутри оверлея NetBird не выходит в публичный интернет
